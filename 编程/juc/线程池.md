## 线程池

为了更好的管理线程，减少线程重复的创建与销毁带来的性能损耗，做到线程复用，也同时为了更好地让CPU发挥其最大功效。

线程池的创建方式推荐根据业务实际情况自行创建，不要使用Excutors工具类下面的几种静态方法创建，那个容易OOM

```
public ThreadPoolExecutor(int corePoolSize,	
                          int maximumPoolSize,
                          long keepAliveTime,
                          TimeUnit unit,
                          BlockingQueue<Runnable> workQueue,
                          ThreadFactory threadFactory,
                          RejectedExecutionHandler handler) {
}
```

参数列表：

##### 	1、corePoolSize：核心线程数。指线程池保留的核心线程的数量，该参数取决于CPU核数与项目的业务类型有关。

##### 		CPU密集型：指计算、统计、算法、加解密、视频处理、逻辑推理等对CPU占用率较高的类型，此种建议设置：CPU核心数+1

##### 		IO密集型：指对文档、数据库等读写操作较频繁，计算较少的类型，如文件的拷贝读取、数据库CRUD，这种对CPU利用率较低，可以增加线程数来发挥CPU的功能，可以设置：2*CPU核心数

##### 	2、maximumPoolSize：最大线程数，规定线程池最多可以创建多少线程。数量=核心线程数+非核心线程数。

##### 	3、keepAliveTime+TimeUnit：非核心线程的最大空闲时间。前为数，后为单位，指非核心线程在没有任务后多久进行销毁。

##### 	4、BlockingQueue：阻塞队列，当核心线程数达到最大并且都在执行任务时，将其他任务放到该队列中等待。这里建议设置ArrayBlockingQueue，并且设置队列长度，以免队列无限扩容导致OOM。

##### 	5、ThreadFactory：指定生产线程的工厂，使用默认即可。

##### 	6、RejectedExecutionHandler：拒绝策略，当任务太多，线程数达到最大且阻塞队列已满时，对执行不了的新任务的处理方式。有四种拒绝策略如下：

##### 		AbortPolicy：放弃任务，并抛出异常。能及时发现系统过载。

##### 		CallerRunsPolicy：让提交任务的线程执行任务。等同于降级处理，会阻塞调用者的线程，适用于非核心任务（日志等）

##### 		DiscardOldestPolicy：丢弃队列中放入最久的一个任务，并把新任务加进队列。适用于对时效性要求高的场景，如实时消息推送。

##### 		DiscardPolicy：直接丢弃任务，不抛异常。



#### 线程池的工作原理：

##### 	1、线程池创建开始，起初还没有创建线程，等待任务提交。

##### 	2、任务提交，开始创建线程，核心线程未满时线程不会复用，会一直创建直到核心线程数量已达设置值。

##### 	3、继续提交任务，任务会放到阻塞队列中。

##### 	4、空闲的核心线程会阻塞在队列头部，有新任务提交则会消费。当阻塞队列放不下了，开始创建新线程。

##### 	5、新线程会一直创建，直到线程池内所有线程数量达到最大设置maximumPoolSize。

##### 	6、所有空余线程均在阻塞队列等待新任务，如果队列已满，且所有线程都在工作，新任务继续提交，则会触发拒绝策略。

##### 	7、等所有线程清空队列且都在空闲后，开始计时，直到设定的空余时间时，将多余核心线程数量的线程一一销毁。



#### 线程池任务提交方式：

##### 	A、execute(): 提交实现Runnable接口的任务。返回值为void。

```java
execute(Runnable command)
```

适用于提交所有线程，有返回值的Callable的任务可以通过new FutureTask(Callable)方式提交，返回结果通过futureTask.get()获取即可。

```java
public static void main(String[] args) {
    ThreadPoolExecutor executor = new ThreadPoolExecutor(13, 200, 10, TimeUnit.SECONDS
            , new ArrayBlockingQueue<>(200),
            new CustomizableThreadFactory()
            , new ThreadPoolExecutor.CallerRunsPolicy());
    try {
        for (int i = 0; i < 200; i++) {
            final int finalI = i;
            //通过使用创建FutureTask对象的方式提交一个Callable任务，返回值可通过futureTask.get()获取
            FutureTask<Integer> futureTask = new FutureTask<>(() -> finalI);
            executor.execute(futureTask);
            System.out.println(Thread.currentThread().getName() + ":" + futureTask.get());
        }
    } catch (Exception e) {
        e.printStackTrace();
    } finally {
        executor.shutdown();
    }
}
```

##### 	B、submit：提交实现Runnable和Callable接口的任务。返回类型均为FutureTask，以此可以获取返回值。Runnable的任务返回值为null。

​	

```java
Future<T> submit(Callable<T> task){}
Future<?> submit(Runnable task){}
```

示例：

```java
    public static void main(String[] args) {
        ThreadPoolExecutor executor = new ThreadPoolExecutor(13, 200, 10, TimeUnit.SECONDS
                , new ArrayBlockingQueue<>(200),
                new CustomizableThreadFactory()
                , new ThreadPoolExecutor.CallerRunsPolicy());
        try {
            for (int i = 0; i < 200; i++) {
                final int finalI = i;
                //提交Callable接口的方式
//                Future<Integer> future = executor.submit(() -> finalI);
                //提交Runnable接口的方式，返回值为null
                Future<?> future = executor.submit(() -> System.out.println(finalI));
                System.out.println("线程返回值==" + future.get());
            }
        } catch (Exception e) {
            e.printStackTrace();
        } finally {
            executor.shutdown();
        }
    }
```

### 注意：

#### 	由于线程池中总会存在一定数量的线程阻塞在那里，所以线程池一定要在使用完成后在finally中主动关闭，否则会产生内存泄漏！！！



### 手写线程池：

明白线程池的工作原理后可手写一个简易的线程池，实现执行任务的功能。

重要的就是worker，worker里定义的成员变量Thread，在线程工厂创建线程时，将worker这个对象直接打包成一个任务，new Thread(this),

在调用Thread.start()即执行worker的run()，在从这里去执行成员变量mission的run()，然后就达成了以新建的线程来执行任务的目的。

同时worker在执行完当前任务后，继续从阻塞队列中拿取任务执行，利用阻塞队列的特点（为空则阻塞消费者，不为空则消费者消费消息）达成worker一直存活的效果。

这里只是实现了执行任务、删除多余线程、关闭线程池的功能，具体的功能可继续扩展。

```java
public class SelfThreadPoolExecutor {

    private Integer corePoolSize;
    private Integer maximumPoolSize;
    private BlockingQueue<Runnable> queue;
    private ThreadFactory threadFactory;

    private static List<WorkerThread> threadList;

    private static volatile boolean shutDown = false;

    //当前的线程数量
    private static volatile AtomicInteger currentThreadNum;


    public SelfThreadPoolExecutor(Integer corePoolSize, Integer maximumPoolSize, BlockingQueue<Runnable> queue, ThreadFactory threadFactory) {
        this.corePoolSize = corePoolSize;
        this.maximumPoolSize = maximumPoolSize;
        this.queue = queue;
        this.threadFactory = threadFactory;
        currentThreadNum = new AtomicInteger(0);
        threadList = new ArrayList<>();
    }


    class WorkerThread implements Runnable {

        //绑定这个worker的启动线程,线程由线程工厂统一创建
        private Thread thread;

        //这个worker的任务
        private Runnable mission;


        public WorkerThread(Runnable mission) {
            this.mission = mission;
            this.thread = threadFactory.newThread(this);
        }

        @Override
        public void run() {

            if (shutDown) {
                return;
            }

            //如果任务不为空，直接启动任务
            Runnable task = mission;
            while (true) {
                if (task != null) {
                    task.run();
                    mission = null;
                }
                //销毁方法，队列为空时，销毁多余的线程，保留核心线程数
                if (queue.isEmpty() && currentThreadNum.get() > corePoolSize) {
                    synchronized (threadList) {
                        if (currentThreadNum.get() > corePoolSize) {
                            threadList.remove(this);
                            currentThreadNum.incrementAndGet();
                            break;
                        }
                    }
                }

                //循环去阻塞队列中取任务
                try {
                    task = queue.take();
                    mission = task;
                } catch (InterruptedException e) {
                    //打断的线程在推出前查看线程池内的线程数量，不够核心线程数的补齐
                    if (!shutDown) {
                        synchronized (threadList) {
                            if (currentThreadNum.get() <= corePoolSize) {
                                threadList.remove(this);
                                threadList.add(addWorker(task));
                            }
                        }
                    }
                    break;
                }
            }
        }
    }

    public void shutDown() {
        shutDown = true;
        for (WorkerThread workerThread : threadList) {
            workerThread.thread.interrupt();
        }
        currentThreadNum = null;
    }

    /**
     * 获取当前线程池内线程数量
     *
     * @return
     */
    public static Integer getThreadListNum() {
        return threadList.size();
    }

    /**
     * 获取当前线程池内线程数量
     *
     * @return
     */
    public static Integer getThreadNum() {
        return currentThreadNum.get();
    }

    private WorkerThread addWorker(Runnable mission) {
        WorkerThread worker = new WorkerThread(mission);
        synchronized (threadList) {
            threadList.add(worker);
        }
        return worker;
    }

    private void enableWorker(Runnable mission) {
        addWorker(mission).thread.start();
    }

    public void execute(Runnable runnable) {
        //1、判断核心线程数是否已超过
        if (currentThreadNum.get() < corePoolSize) {
            //小于则创建线程，执行任务
            enableWorker(runnable);
            currentThreadNum.incrementAndGet();
        } else {
            //查看队列是否已满
            if (!queue.offer(runnable)) {
                //队列已满，查看有没有到达最大线程数
                if (currentThreadNum.get() < maximumPoolSize) {
                    enableWorker(runnable);
                    currentThreadNum.incrementAndGet();
                } else {
                    //都满了，抛异常
                    System.out.println("任务已满，已丢掉 : " + runnable.toString());
                }
            }
        }
    }

}
```
