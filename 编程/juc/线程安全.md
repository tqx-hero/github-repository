### 线程安全：

#### 	1、JMM要解决的三大难题：

​		JMM（java Memory Model）是java内存模型，是对java语言定义的规范。

​	java内存模型分为了变量共享区域（对应CPU缓存模型的内存+L3区域）和线程独立的工作内存区域（对应CPU的L1、L2区）。

​	JMM需要解决的三大问题为：

​		1、原子性：即每一步的操作不可再次分割，如： i = 10；像 int i=10就不满足原子性，这个是分为三步执行的：先分配内存空间，给空间地址赋值，把数据的内存地址赋给i。

​		2、可见性：数据的读写必须保证可见，尤其是在一个线程修改后的数据，必须保证其他线程能立即感知到并能获取新值。

​		3、有序性：对单线程而言，指令重排后程序的执行前后结果必须保证一致，做到happens-before与as-if-serial语义。



### 	2、synchroinzed：

​		也叫同步锁、排它锁，是java中常用的一种锁。

​		synchroinzed可保证了以上三大问题均可实现，步骤如下：

​		1、对目标对象加锁时，强制清空工作内存中的对象，使其先去共享内存中读取到该对象的新值，解锁后会强制刷新新值到内存，并使其他线程感知，保证可见性。

​		2、被该关键字修饰的代码块中所有代码只能由持有锁的线程执行，保证了原子性。

​		3、以该代码块为界，禁止上下区域的指令重排，等同于内存屏障，保证了有序性。



##### 	但是它不能保证临界区内的代码的指令重排，所以临界区内的执行代码越短越好，需要考虑临界区内对变量的修改是否需要用volatile禁止指令重排。



#### ThreadLocal：

​	线程安全，放入的value是线程隔离的，所以即使是共享的threadLocal，对于get和set值均线程安全。

​	但是一定要注意，使用ThreadLocal基本是在线程池中使用，线程池宗旨是线程复用，而ThreadLocal中数据是线程隔离，一旦线程复用，线程中的ThreadLocalMap存放的ThreadLocal与value的键值对将会越来越多，并且value为强引用，导致gc回收不掉内存泄漏，并且线程复用导致垃圾对象越来越多，最终结果就是内存溢出。

​	所以在使用ThreadLocal，尤其是在线程池这种线程复用的地方，使用完成后一定要及时remove，否则会导致内存泄漏。

```java
public class ThreadLocalTest {

    public static ThreadLocal<User> local = new ThreadLocal<>();

    public static void main(String[] args) {

        ThreadPoolExecutor executor = new ThreadPoolExecutor(12, 200, 10, TimeUnit.SECONDS
                , new ArrayBlockingQueue<>(300)
                , new DefaultManagedAwareThreadFactory(),
                new ThreadPoolExecutor.CallerRunsPolicy());

        try {
            for (int i = 0; i < 40; i++) {
                  executor.execute(() -> {
                    try {
                        local.set(new User());
                    } catch (Exception e) {
                    } finally {
                        //任务结束时一定要手动清除ThreadLocal，保险的做法就是在finally中防止任务执行出现异常。
                        local.remove();
                    }
            }
        } catch (Exception e) {
        } finally {
            executor.shutdown();
        }
    }
}
```
