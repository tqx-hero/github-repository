## 事务：

### 一、事务的四大特性：

#### 	原子性：同一事务中操作要么全部执行，要么全部回滚。

#### 	一致性：在事务提交前后数据保持一致。（取钱之前与取钱之后钱的总数没变）

#### 	隔离性：并发情况下事务与事务之间是隔离的。

#### 	持久性：事务一旦提交成功数据会永久改变。



### spring使用事务：

​	springboot中开启事务只需要在方法或类上声明：@Transactional即可，关于事务管理器TransactionManager和开启事务的@EnableTransactionManagement，springboot已经自动装配完成。



​	但是在spring中，事务管理器与开启事务都需要自己配置。以下是spring中都需要自行配置的（JdbcTemplate根据需要自行选择）：

```java
@Configuration(proxyBeanMethods = false)
@EnableTransactionManagement
public class DataSourceConfig {

    @Value("${spring.datasource.driver-class-name}")
    private String driverClassName;
    @Value("${spring.datasource.url}")
    private String url;
    @Value("${spring.datasource.username}")
    private String username;
    @Value("${spring.datasource.password}")
    private String password;

    @Bean
    public DataSource dataSource() {
        DriverManagerDataSource dataSource = new DriverManagerDataSource();
        dataSource.setDriverClassName(driverClassName);
        dataSource.setUrl(url);
        dataSource.setUsername(username);
        dataSource.setPassword(password);
        return dataSource;
    }

    @Bean
    public JdbcTemplate jdbcTemplate(DataSource dataSource) {
        return new JdbcTemplate(dataSource);
    }

    @Bean
    public TransactionManager transactionManager(DataSource dataSource) {
        return new DataSourceTransactionManager(dataSource);
    }

}
```



### 二、事务的传播特性（Transaction Propagation）：

##### 首先声明，同一个类下的方法嵌套，被嵌套的方法无论有无注解都不会开启新事务，他们的事务都会根据最外边的方法决定，自身开启的事务均会失效。

##### 因为@Transactional注解实现方式是spring通过对该注解所在的类生成代理对象，开启关闭事务都是在代理类进行的，如果同一个类下面嵌套调用，等同于被代理对象直接调用它的内部方法，不会经过代理类，所嵌套的事务当然不会生效。

##### 处理方法有：

##### 	 · 通过AOP上下文获取当前类的代理类，然后再去调用方法，让方法调用从代理类经过，嵌套的方法事务则会生效

```java
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Service
public class OrderService {

    // 外层方法（无事务）
    public void createOrder() {
         // 关键：通过AopContext获取代理对象，再调用方法
        ((OrderService) AopContext.currentProxy()).addOrderItem();
        System.out.println("订单创建完成");
    }

    // 内层方法（声明了事务）
    @Transactional(rollbackFor = Exception.class)
    public void addOrderItem() {
        // 模拟数据库操作
        System.out.println("添加订单项（理论上应开启事务）");
        // 即使这里抛异常，也不会回滚，因为事务未生效
        throw new RuntimeException("模拟数据库操作失败");
    }
}
```

##### 	· 将相关代码添加到另一个类

##### 	·外层方法添加事务

#### spring声明的7大传播特性如下：

#### ·REQUIRED

##### 	默认，上层有事务就融入上级的事务，没有事务就重新开启事务。

#### ·SUPPORTS

##### 	上层有事务嵌套就融入上级事务，没有则不开启事务。适用于日志查询等非核心查询操作。

##### 	注意如果最外层以该特性声明事务，若方法内部嵌套有修改数据库的事务，内部的所有事务都会失效！

#### ·REQUIRED_NEW

##### 	无论上级有没有开启事务，均会开启新的事务

##### 	适合无论上级事务是否回滚，都不会影响本级的事务

#### ·NOT_SUPPORTED

##### 	无论外部有没有事务均不开启事务

#### ·NEVER

##### 	外部没事务则不开启，有事务则抛异常

#### ·MANDATORY

##### 	外部没事务抛异常，有事务就融入。

#### ·NESTED

##### 	外部没事务则开启事务，有事务则融入，外层影响内层，但内层不会影响外层。



### 三、设置事务只读（readOnly）

​	只会设置在查询方法中。

```java
connection.setReadOnly(true);
```

数据库会对只读做相关优化，至于优化内容，具体需要看不同的数据库类型。

设置了只读属性后，该方法如果进行增删改操作会抛出异常。

### 四、超时时间（timeout）

​	指定事务等待的最长时间，单位为秒。

### 五、异常属性：

#### rollbackFor，默认为只回滚RuntimeException的异常，其他异常不会回滚。在开发时必须设置这个属性：

```java
@Transactional(rollbackFor = Exception.class)
```

### 六、事务失效：

##### 	失效原因有以下几种：

###### 		1、没有注入spring容器（@Compont、@Bean等方式）；

###### 		2、类的修饰符为private，CGLIB无法继承作为父类，所以无法创建代理类。

###### 		3、没有配置rollBackFor属性，当抛出IO异常或ClassNotFound等非运行时异常时不回滚。

###### 		4、同类方法调用，如果嵌套的方法有事务，则事务失效，因为是同类调用，不会经过代理对象的事务开启关闭。

##### 		可以通过用AOPContext获取当前代理对象来执行方法。

```java
((UserService)AopContext.currentProxy()).insert(22, "name");
```

​	同时必须在启动类上添加开启aopProxy曝光的注解：

```java
@EnableAspectJAutoProxy(exposeProxy = true)
```



依赖也不能少：

```java
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-aop</artifactId>
        </dependency>
```

###### 		5、方法中用try{}catch{}代码块捕捉了异常，自行处理了，导致代理类没捕捉到异常，继续提交事务。

###### 6、多线程。如在一个线程里重新开启另一个线程去执行数据库操作，若子线程抛异常且子线程存在事务，则子线程的数据回滚，主线程数据不会回滚。

###### 	原因是当线程执行时，事务管理器会将当前事务的数据库连接connection存放到ThreadLocal里，所以说数据库的连接信息与线程绑定。而开启子线程后，子线程去ThreadLocal中拿取不到连接信息，就会去创建新的事务，所以事务是和线程绑定到一起的，做到了线程隔离。

###### 解决方案如下：

##### 1、在当前类中注入数据源DataSource；

##### 2、以DataSource为key去TransactionSynchronizationManager这个事务管理器内拿到对应主线程ThreadLocal中存储的连接信息；

##### 3、若有同一类的嵌套调用，则需要通过启动类上声明开启曝光AOP代理类的注解：@EnableAspectJAutoProxy(exposeProxy = true)

##### 4、在子线程ThreadLocal中添加数据源等进行绑定：TransactionSynchronizationManager.bindResource(dataSource, finalSourceValue);

##### 5、同类的嵌套调用时，在主线程中获取代理对象，然后在子线程中去执行方法，不能直接在子线程中获取代理对象，因为代理对象也是通过ThreadLocal线程绑定的，也是线程隔离。若没有，则直接用注入的对象调用方法即可。

##### 具体代码如下：

```java
//通过依赖注入获取数据源：DataSource
    @Resource
    private DataSource dataSource;
	@Transactional
    public int mixedService() throws InterruptedException {
        orderService.insert(11, "zhangsan");
//        userService.update(2, "zhangsan1");
//        insert(3, "夏侯渊");
//        Map<Object, Object> resourceMap = TransactionSynchronizationManager.getResourceMap();
//        Object sourceValue = null;
//        for (Map.Entry<Object, Object> entry : resourceMap.entrySet()) {
//            sourceValue = entry.getValue();
//            break;
//        }
      //  DataSource dataSource = transactionManager.getDataSource();
//        Object finalSourceValue = sourceValue;
        UserService proxy = (UserService) AopContext.currentProxy();
        Object finalSourceValue = TransactionSynchronizationManager.getResource(dataSource);
        Thread tl = new Thread(() -> {
            TransactionSynchronizationManager.bindResource(dataSource, finalSourceValue);
            //这里是同类嵌套调用的情况，代理对象需要再主线程获取，然后子线程拿到主线程中获取的代理类执行
            proxy.insert(22, "name");
            //其他情况则正常调用即可
            orderService.add(name);
        }
        );
        tl.start();
        tl.join();

        return 0;
    }
```
