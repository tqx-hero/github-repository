### 调试：

- #### 使用宏定义:

  `#ifdef` 或`#ifndef`宏定义,在需要打印调试信息的地方进行设定,在编译时根据是否添加定义的宏来确定是否执行if内部的代码：

  ```c
  #include <stdio.h>
  //debug的使用
  int main(){
          #ifdef DEBUG	//设定宏DEBUG，当编译器添加宏定义DEBUG时，才会执行这内部的代码
                  printf("debug...\n");
                  printf("这是第:%d行,编译时间是:" __TIME__ "\n",__LINE__);
                  printf("编译日期= " __DATE__ ",当前文件 : " __FILE__ "\n" );
      			printf("当前函数名 = %s\n",__FUNCTION__);
          #endif
          printf(".....\n");
          return 0;
  }
  ```

  输出结果：

  ```bash
  $gcc test.c -o test -DDEBUG
  $./test
  
  debug...
  这是第:6行,编译时间是:11:41:39
  编译日期= Oct 23 2026,当前文件 : test.c
  ```

  上述调试不但使用了宏，还是用了编译器的预处理宏：

  下面是预处理阶段编译器可以获取到的文件的信息。

  | 宏               | 说明                                        |
  | ---------------- | ------------------------------------------- |
  | \_\_LINE\_\_     | 当前代码的行号(整型)                        |
  | \_\_FILE\_\_     | 当前的文件名(字符串)                        |
  | \_\_TIME\_\_     | 编译器编译时的时间，格式为hh:mm:ss(字符串)  |
  | \_\_DATE\_\_     | 编译时的日期，格式为: mmm  dd  yyyy(字符串) |
  | \_\_FUNCTION\_\_ | GCC扩展，显示当前函数名(字符串类型)         |

- #### 断言：

  ```c
  #include <assert.h>
  
  struct {
          unsigned char cmd_type, offset, stride, count;
  } scalars;
  //scalar由四个char类型组成的结构体，可以看成一个无符号int类型
  //断言函数当参数表达式expression的值为真(C语言中非0为真)，程序继续执行，为假(expression ==0),程序会调用abort()退出进程
  void assert(scalar expression);
  ```

- #### 对堆内存的申请，释放调试：

  测试程序 `mallocleak.c` 源码：

  ```c
  #include <stdlib.h>
  #include <stdio.h>
  
  int main(){
          char* ptr = (char*)malloc(1024);
          ptr[1024] =0;	//访问越界，应该抛出段错误。
          return 0;
  }
  ```

  上面的程序向堆内存申请了1024B的空间，但是`ptr[1024]=0`这个地址空间不包括在内，当前程序访问越界了，并且程序也没释放内存。

  通过gcc编译执行时，该程序能正常执行，如果程序不会退出的话，访问越界与内存泄露问题就会导致其他进程出现问题。

  - ##### 使用三方库Electric-Fence，可以在启动时对程序进行越界检查，出现越界访问会向进程发送SIGSEV信号。

    ```bash
    #ubuntu安装
    sudo apt install electric-fence
    #centOS安装
    yum install electric-fence
    ```

    安装完成后，在编译时使用：

    ```bash
    gcc mallocleak.c -o mallocleak -lefence
    ```

    运行时会抛出异常：

    ```bash
    $ ./mallocleak
    #运行时检测到访问越界，发送SIGSEV信号，终止进程
      Electric Fence 2.2 Copyright (C) 1987-1999 Bruce Perens <bruce@perens.com>
    Segmentation fault (core dumped)
    ```

    > 每次 malloc 分配内存时，在内存块的紧挨着后面（或前面）放一个无权限保护页；一旦越界读写就触发缺页异常，程序 coredump；free 之后这块内存也标记为不可访问，释放后再访问立刻崩溃。
    >
    > 缺点：**非常吃内存，每个分配至少占一整页**，不适合大压力程序；现在工程上更多用 valgrind、asan；efence 偏老，笔试 / 嵌入式底层调试还会见到。

  - ##### 使用GCC内置的ASan：

    ​	**ASan 是 GCC / Clang 内置的内存错误检测器，编译器插桩 + 运行时库，不需要单独安装包**，编译加参数 `-fsanitize=address` 即可开启，是现在 C/C++ 开发首选内存检测工具。

    

    ##### 原理：

    > ASan 由两部分组成：**编译器插桩 + libasan.so 运行时库**

    1. 影子内存 Shadow Memory

       64 位 Linux 下：

       应用每 8 字节内存，对应 1 字节影子内存

       ，记录这 8 字节的有效状态（中毒标记 poisoned）计算机研究...

       - 影子字节 = 0：全部 8 字节合法可读可写
       - 影子字节 ∈ [1,7]：前面 N 字节有效，后面中毒
       - 负数（0xf9、0xfd、0xf8 等）：**中毒（invalid），访问直接报错** 编译器在每一条 load/store 之前插入检查代码：先查影子内存；如果是中毒区域，立刻打印报错栈并终止程序。

    2. **红区 Redzone** malloc、栈变量、全局变量的**前后都会插入一块被标记中毒的红区**。一旦读写踩到红区，直接捕获越界。

    3. **隔离队列 Quarantine（use-after-free 关键）** free 之后，内存**不会立刻还给系统**，而是放进隔离队列，标记为中毒；一段时间内如果再次访问这块内存，直接捕获 use-after-free；队列满了才真正回收复用。

    > 和 efence 区别：efence 是硬件页保护（一页 4K）；ASan 是细粒度影子标记，红区很小，内存开销可控。

    

    ###### 能检测的错误有：

    1. `heap-buffer-overflow` 堆越界（上溢 / 下溢）
    2. `stack-buffer-overflow` 栈数组越界
    3. `global-buffer-overflow` 全局变量越界
    4. `heap-use-after-free` free 之后继续访问（野指针）
    5. `stack-use-after-scope` 局部变量出作用域后访问
    6. `stack-use-after-return` 返回栈地址并在外层访问
    7. `double free`、多次 free、非法 free
    8. `alloc-dealloc-mismatch` malloc 和 delete 混用、new 和 free 混用
    9. 内存泄漏（由 LSan 子模块负责，ASan 默认开启泄漏检测）

    > ASan **不能检测**：野指针指向未分配的随机地址、栈溢出攻击那种超大栈溢出；也不检查未初始化内存（这个是 MSan）

    ###### 使用方法：

    编译加参数 `-fsanitize=address` 即可开启。

    ```bash
    # gcc/g++ 编译、链接都要带上 -fsanitize=address
    gcc -g -fsanitize=address test.c -o test
    ./test
    ```

    推荐组合（栈信息更清晰）：

    ```bash
    gcc -g [-O1] -fsanitize=address -fno-omit-frame-pointer test.c -o test
    ```

    - `-g`：保留调试符号，报错能显示源码行号
    - `-O1`：推荐带优化；完全 - O0 插桩太重、速度很慢；O2/O3 也能用，但栈信息差一点
    - `-fno-omit-frame-pointer`：保留栈帧指针，调用栈更干净

    **环境变量控制 ASan 行为：**

    ```bash
    # 关闭泄漏检测
    ASAN_OPTIONS=detect_leaks=0 ./test
    # 开启栈use-after-return检测
    ASAN_OPTIONS=detect_stack_use_after_return=1 ./test
    ```
