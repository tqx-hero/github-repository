### 线程LWP(Light Weight Process)：

#### 安装线程说明书man：

```bash
sudo apt-get install manpages-posix-dev
```

###### 线程是缩小版的进程，是CPU运行的基本调度单位。

###### 进程是OS分配资源的最基本单位，一个进程中可以创建多个线程。

###### 同一个进程中的线程共享进程中的代码段(text)、数据段(data)、堆(heap)、BSS段(存放未初始化的静态变量、全局变量，初始化进程时，内核会将该区域全部清空，所以未初始化的静态变量、全局变量的初始值为0)。

###### 线程私有的有：程序计数器PC(EIP+CS)、栈(程序执行的重要内存空间)。

###### 在Linux中，实现线程与进程底层都是调用了clone()，所以两者除了体量之外差别不大。



#### 线程的优缺点：

###### 优点：

- ​	轻量，创建、销毁、切换开销更小。
- ​    不同线程之间的数据通信、共享数据更方便，不需要额外使用管道、消息队列、共享内存等。
- ​    程序并发性提高。

###### 缺点：

- ​    库函数不稳定。
- ​    GDB调试不支持导致调试困难。
- ​     对信号支持不友好。



#### 注意事项：

**1、pthread_*函数为POSIX标准的第三方库函数，该函数的定义绝大多数都在头文件\<pthread.h\>中，在编译时必须添加动态链接选项-l用来指明第三方库pthread。如：编译文件为p.c:**

```bash
gcc p.c -o a.out -lpthread 
```

**2、在多线程程序中，如果要实现代码的可重入，必须定义宏：#define _REENTRANT。这个宏必须在所有引入头文件之前。它的作用如下：**

- ###### 对部分函数重新定义可重入版本，可重入版本的函数名在原函数名基础上增加了后缀"_r"，如原函数gethostbyname的可重入版本变为gethostbyname_r。

- ###### stdio.h中原先以宏形式实现的某些函数变成可安全重入的函数。

- ###### errno.h中定义的变量errno将成为一个函数调用，使得能够以多线程安全的方式获取真正的errno值。



#### 获取线程ID句柄-pthread_self(3)：

POSIX.1 标准允许实现在选择用于表示线程 ID 的类型时拥有很大自由度；例如，既可以使用算术类型，也可以使用结构体来表示。因此，pthread_t 类型的变量不能使用 C 语言相等运算符（==）进行可移植的比较；应当改用 **pthread_equal** (3)。

线程标识符应被视作不透明类型：除了在 pthreads 系列函数调用中使用线程 ID 之外，任何其他使用方式都不具备可移植性，并且可能产生未定义的结果。

线程 ID 仅在同一个进程内保证唯一。当一个已终止线程被连接回收，或者一个分离线程终止后，它的线程 ID 可能会被复用。

**pthread_self () 返回的线程 ID，与调用 gettid (2) 得到的内核线程 ID 并不是同一个东西。**

**前者返回的是pthread库层面的线程ID(也可以叫做用户态ID)，后者获取到的是内核层面执行该程序的真实线程的ID(内核态ID).在Linux系统中，pthread_t本质是线程栈的起始地址，所以可把它仅仅当做一个指针，是pthread库函数操作线程的一个句柄，并不是真正线程的ID。**

```c
#include <pthread.h>
typedef unsigned long int pthread_t;	//Linux下为无符号long类型，其他系统可能为结构体
//返回当前线程的ID，该函数总是成功.
pthread_t pthread_self(void);
```

#### 线程创建pthread_create：

###### 注意：

***函数返回值没有使用类Unix系统标准(0代表成功，-1失败且errno为错误码)，而是在函数失败时直接返回错误码而不是-1***

```c
#include <pthread.h>
/**
	thread:
		pthread_t的存储地址。
		pthread_create () 调用成功时，会在返回前将新线程 ID 存入 thread 指向的缓冲区；该标识符用于后续调用其他 pthread 系列函数时引用此线程。
		
	attr:
    	指向 pthread_attr_t 类型结构体，创建线程时会使用该结构体的内容来设定新线程属性；
    	该结构体由 pthread_attr_init (3) 及相关函数初始化。若 attr 为 NULL，则使用默认属性创建线程。
		默认方式如下：
			1、继承创建线程的信号掩码(pthread_sigmask (3)).
			2、未决信号集设置为空(sigpending(2)).
			3、不会继承创建线程的信号栈(sigaltstack(2)).
			4、继承创建线程的浮点环境(fenv(3)).
			5、新线程的CPU时间时钟初始化为0(参见 pthread_getcpuclockid (3)).
			Linux特有：
			6、新线程会复制继承调用线程的权限集（参见 capabilities (7)）与 CPU 亲和性掩码（参见 sched_setaffinity (2)）
	
	start_routine：新线程创建成功后要执行的函数。
	arg: 传入第三个参数start_routine函数的唯一参数。
	
	return：
		成功： 返回0.
		失败： 返回错误码
		错误码如下：
			EAGAIN：已达到系统对线程数量设置的上限，资源不足，无法创建新线程。
				可触发该错误的限制有多种：
					1、已达到 RLIMIT_NPROC 软资源限制（通过 setrlimit (2) 设置）。
						该限制限定单个真实用户 ID 可拥有的进程与线程总数；
					2、已达到内核全局进程与线程上限 /proc/sys/kernel/threads-max（参见 proc (5)）；
					3、已达到 PID 最大值 /proc/sys/kernel/pid_max（参见 proc (5)）。
			EINVAL：attr 中的设置无效。
			EPERM：没有权限设置 attr 中指定的调度策略与调度参数。
*/
int pthread_create(pthread_t *thread, const pthread_attr_t *attr,
                   void *(*start_routine) (void *), void *arg);

```

##### 新线程可通过以下任一方式终止：

- ###### 调用 pthread_exit (3)，指定一个退出状态值，同一进程内的其他线程可调用 pthread_join (3) 获取该值。

- ###### 从 start_routine () 函数返回。这等价于调用 pthread_exit (3)，并将 return 语句中的返回值作为入参。

- ###### 被取消（参见 pthread_cancel (3)）。

- ###### 进程内任意线程调用 exit (3)-(exit作用就是终止当前进程，并将status & 0xFF返回给父进程)，或主线程从 main () 函数返回(return 会将主线程，也就是当前进程弹栈退出)。这会终止该进程内的所有线程。



###### demo1：创建线程，shell通过进程ID查看线程：

```c
#include <sys/syscall.h>
#include <pthread.h>
#include <unistd.h>
#include <stdio.h>
#include <stdlib.h>
//创建线程，并执行打印任务

void* printf_cnt(void* arg){
        pid_t pid,tid;
        tid = syscall(SYS_gettid);
        pid = getpid();
        while(1){
                sleep(1);
                printf("子线程 id = %d,进程ID = %d\n",tid,pid);
        }
}

int main(){
        pthread_t pt,pt1;
        if((pthread_create(&pt,NULL,printf_cnt,NULL)) != 0){
                fprintf(stderr,"创建线程失败\n");
                exit(-1);
        }
        if((pthread_create(&pt1,NULL,printf_cnt,NULL)) != 0){
                fprintf(stderr,"创建线程失败\n");
                exit(-1);
        }
        pid_t pid = getpid();
        while(1){
                sleep(1);
                printf("主线程 id = %d\n",pid);
        }
        return 0;
}
```

###### demo2：线程的创建与回收：

```c
#include <pthread.h>
#include <unistd.h>
#include <stdio.h>
#include <stdlib.h>
//创建线程，并执行打印任务

void* printf_cnt(void* arg){
        int cnt = (int)(long) arg,i;
        for(i=1;i <= cnt;++i)
                printf("子进程执行第[%d]打印任务...\n",i);
        printf("子进程打印任务完成,正在退出\n");
        pthread_exit(0);
}

int main(){
        pthread_t pt;
        int i =10;	//将主线程中的参数传入新线程，这里为了简化直接强转传入，更优雅的方式是传入一个结构体指针(堆上的)
        if((pthread_create(&pt,NULL,printf_cnt,(void*)(long)i)) != 0){
                fprintf(stderr,"创建线程失败\n");
                exit(-1);
        }
        pthread_join(pt,NULL); //等待某个线程执行完成，回收它的TCB，等同于进程中的wait*(2)
        printf("主线程退出..\n");
        return 0;
}
```



#### 线程的回收pthread_join(3)：

###### 同进程一样，线程在创建时，内核会为线程创建TCB(Thread Control Block),在线程退出时，必须由其他线程回收该线程的TCB资源，否则会导致内存泄漏。

```c
#include <pthread.h>
/**
	阻塞等待线程终止，回收资源。函数会等待 thread 指定的线程终止。如果该线程已经终止，那么 pthread_join () 会立即返回。
	thread: 要回收的线程句柄。
	
	retval：存放退出的线程在退出时的返回值的指针。
		为NULL，不会捕获回收线程的返回值。
		如果 retval 不为NULL，pthread_join () 会将目标线程的退出状态（即目标线程传递给 pthread_exit (3) 的值）复制到 retval 指向的内存位置。
		如果目标线程被取消，则 PTHREAD_CANCELED 会被存入 retval 指向的位置。
		如果多个线程同时尝试对同一个线程执行连接操作，行为结果未定义。
		如果调用 pthread_join () 的线程被取消，那么目标线程仍将保持可连接(join)状态（即不会被分离detach）。
		
	return：
		成功：0.
		失败返回错误码，错误码如下：
			EDEADLK：
				检测到死锁（例如，两个线程尝试互相等待对方结束）；或者传入的线程就是调用线程本身。
			EINVAL：
				该线程不可被等待回收。
			EINVAL:
				已有其他线程正在等待回收此线程。
			ESRCH:
            	找不到具有该 ID 的线程。
*/
int pthread_join(pthread_t thread, void **retval);
```

###### 成功调用 pthread_join () 之后，调用者可以确定目标线程已经终止。随后调用者可以执行线程终止后所需的任何清理操作（例如释放分配给目标线程的内存或其他资源）。

###### 对一个已经经过pthread_join()回收的线程不能再次被回收。

###### 对于未使用pthread_join回收的线程，在退出后由于资源没有被释放会产生 “僵尸线程”。应避免这种情况，因为每个僵尸线程都会占用一定系统资源，当僵尸线程累积到一定数量后，系统将无法再创建新线程（或进程）。

###### pthreads 中没有与 waitpid (-1, &status, 0) 对应的接口，也就是不存在 “等待任意已终止线程” 的操作。如果你认为需要该功能，大概率需要重新考虑应用程序的设计。

###### 同一进程内的所有线程地位平等：进程中的任意线程都可以对该进程内其他任意线程执行连接操作。

##### demo：创建子线程，子线程在堆上开辟空间，输入数据，退出时返回传到主线程，主线程负责输出并释放堆内存防泄漏。

```c
#include <pthread.h>
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <string.h>

void* pth_exec(void* arg){
        printf("子线程已经执行，正在退出\n");
        //exit(0); //子线程中不要使用exit(2),该函数会导致进程退出，而不是线程退出，可以使用pthread_exit或return
	    //注意：返回值除了基本数据类型，指针类型必须要在堆上，不要返回栈上的。
    	//另外，由于C是面向过程编程，没有对象概念，结构体必须以指针类型传递，深浅拷贝是面向对象语言(C++/JAVA..)的处理过程。
        char* buf = malloc(sizeof(char)* 64);
        strcpy(buf,"大家好才是真的好!");		
        pthread_exit(buf);	//使用return buf也可以。
}

int main(){
        pthread_t pt;
        if(pthread_create(&pt,NULL,pth_exec,NULL) != 0){
                fprintf(stderr,"创建线程失败\n");
                exit(-1);
        }
        printf("创建线程成功!\n");
        char* buf;
        if(pthread_join(pt,(void**)&buf) != 0){ //传参为指针的地址，并将其强转成二级通用指针。
                fprintf(stderr,"子线程回收失败\n");
                exit(-1);
        }
        printf("子线程回收成功,返回信息 = %s\n",buf);
        //回收内存
        free(buf);
        return 0;
}
```



#### 剥离线程pthread_detach(3):

设置线程的属性为分离态。当分离态的线程终止，它的TCB资源会自动被内核回收，而不需要由其他线程join回收。

**已经被分离的线程不能再进行detach或join.**

**在pthread_create创建线程时的第二个参数attr，可以通过pthread_attr_setdetachstate(3)提前设置attr的可分离属性值，使得线程在创建后直接就是可分离的。**

**该函数无法获取子线程的返回值。**

```c
#include <pthread.h>
/**
	thread: 被分离的线程
	return：
		成功：0
		失败：
			错误码,错误码如下：
			EINVAL: 线程不可回收
 	        ESRCH： 线程ID找不到。
*/
int pthread_detach(pthread_t thread);

Compile and link with -pthread.
```

###### demo：使用detach代替join回收线程TCB

```c
#include <pthread.h>
#include <unistd.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
//设置detach属性

void * th_callback(void* arg){
        sleep(3);
        printf("线程退出\n");
}

int main(){
        pthread_t pdt;
        pthread_create(&pdt,NULL,th_callback,NULL);
        pthread_detach(pdt);
        while(1);
        return 0;
}
```



#### 线程的退出pthread_exit(3)与取消pthread_cancel(3)：

**子线程不要轻易使用exit(3)与_exit(2).这两个函数都是退出当前进程，这会让进程内所有线程全部杀死。**

**pthread_exit(3)为线程主动退出，pthread_cancel(3)为其他线程给参数为thread的线程发送信号，令其退出。**

**主线程使用pthread_exit(3)时，只会退出主线程，不会退出进程，所以其他子线程都不会受影响。**

```c
#include <pthread.h>
/**
	retval: 线程退出时的返回值， return retval；
	该函数总是成功。
*/
void pthread_exit(void *retval);
/**
	pthread_cancel () 函数向线程 thread 发送取消请求。目标线程是否响应以及何时响应该取消请求，取决于由该线程自身控制的两个属性：其可取消状态state与可取消类型type。
	
	线程的可取消状态由 pthread_setcancelstate (3) 设置，可以为启用enabled（新建线程的默认值）或禁用disabled。
	若线程禁用了取消功能，则取消请求会保持排队，直到该线程启用取消。
	若线程已启用取消，则由其可取消类型决定何时发生取消操作。
	
	线程的可取消类型由 pthread_setcanceltype (3) 设置，可以是异步型asynchronous或延迟型deferred（新建线程的默认值）。
	异步可取消意味着该线程可在任意时刻被取消（通常会立刻执行，但系统不保证一定如此）。
	延迟可取消则表示取消操作会被推迟，直到线程下一次调用属于取消点(cancellation point)的函数。
	pthreads (7) 中列出了属于或可能作为取消点的函数。
	
	当一个线程被取消后，只能通过pthread_join(3)获取该线程的取消状态：PTHREAD_CANCELED
	thread: 
		要取消的线程句柄。
	return：
		成功：0
		失败：返回失败码，失败码如下：
		ESRCH : 线程ID没找到
*/
int pthread_cancel(pthread_t thread);
Compile and link with -pthread.
```



#### pthread_setcancelstate(3)、pthread_setcanceltype(3)：

pthread_setcancelstate(3)可以设置线程是否能被取消.

pthread_setcanceltype(3)可以设置线程的取消类型。

```c
#include <pthread.h>
/**
	state: 要设置的线程状态，下方状态必须选一个
		PTHREAD_CANCEL_ENABLE(枚举值0):
			线程可取消。默认选项，包括init线程。该选项可以接受线程进入取消流程。
		PTHREAD_CANCEL_DISABLED(枚举值1)：
			线程不可被取消。该选项设置后，收到的取消线程请求会被阻塞，直到取消状态变成enable。
	oldstate：
		如果地址不为NULL，会将旧的state放入该地址。
		为NULL则忽略该参数。考虑可移植性的话，该值应该不为NULL。
		Linux 的线程实现允许 pthread_setcancelstate () 的 oldstate 参数为 NULL，这种情况下不会向调用者返回先前可取消状态的相关信息。许多其他实现同样允许 oldstate 参数传入 NULL，但 POSIX.1 并未对此作出规定，因此可移植应用程序应当始终为 oldstate 指定非空值。对于 pthread_setcanceltype () 的 oldtype 参数，也存在完全类似的情况
	return：
		成功： 0.
		失败： 错误码。
			EINVAL：state参数不合法。
*/
int pthread_setcancelstate(int state, int *oldstate);
/**
	type:
		PTHREAD_CANCEL_DEFERRED(枚举值0):
			取消请求会被延迟，直到该线程下次调用属于取消点的函数（参见 pthreads (7)）。
				- 取消点的函数大部分都是系统调用、等待I/O、带阻塞线程的函数，比如sleep()、accept()/open()/read/write...
				取消点有多个：
				1、某些函数进入函数即检查；
				2、系统调用：
					如果出现阻塞时，内核唤醒线程，返回EINTR,libc检查未决信号；比如使用管道，填满管道前提下再往里面write，会阻塞，此时触发这种情况。
					不出现阻塞，syscall返回成功后检查。典型printf("...\n"),\n刷新缓冲区write写入无阻塞，会在终端输出信息后触发检查。
			这是所有新建线程（包括初始线程）默认的可取消类型。
			即便采用延迟取消，异步信号处理程序中的取消点仍可能生效，其效果等同于异步取消。
		PTHREAD_CANCEL_ASYNCHRONOUS(枚举值1):		
			线程可在任意时刻被取消。（通常，线程收到取消请求后会立刻被取消，但系统并不保证这一点。）
			异步可取消性日常极少用到，因为它能让线程随时能取消，并不能保证正常回收完成所有线程使用的资源，有可能导致内存泄漏。
			为数不多的适用场景之一，是取消一个正在执行纯计算密集型循环的线程。
			这些函数执行的设置与获取操作，相对于进程内其他调用同一函数的线程而言是原子操作。
			该选项取消的线程返回值为NULL
	oldtype：
		如果地址不为NULL，会将旧的type放入该地址。
		为NULL则忽略该参数。考虑可移植性的话，该值应该不为NULL。
	return：
		成功： 0.
		失败： 错误码。
			EINVAL：type参数不合法。
*/
int pthread_setcanceltype(int type, int *oldtype);
/**
	立刻检查线程是否被取消。用于没有系统调用或者需要主动检查线程是否被取消的场景。
	当线程未决信号集存在取消信号，该函数会触发执行取消流程。
	即使不存在取消信号或者取消状态不可用setcancelstate(PTHREAD_CANCEL_DISABLED,..),调用该函数不受影响。
*/
void pthread_testcancel(void);
Compile and link with -pthread.
```

#### 线程的属性pthread_attr_*(3)：

可以使用对应函数设置线程的属性，包括栈的位置、大小，是否可分离(join)，优先级，是否可继承线程属性等。

```c
//线程的属性(伪代码)：
struct pthread_attr_t{
    int detachstate;	//线程分离状态
    int schedpolicy;	//调度方式
    struct sched_param schedparam; //与schedpolicy相关，对调度的具体控制
    int inheritsched;	//继承创建线程使用的参数。
    int scope; //控制线程调度的计算方式
    size_t guardsize;	//线程栈末尾警戒缓冲区大小.当栈实际使用量超过这个值，会提醒。
    int stackaddr_set;	//线程栈设置
    void* stackaddr;	//栈地址
    size_t stacksize;	//栈大小
}pthread_attr_t;

struct sched_param {
    int sched_priority;     /* Scheduling priority */
};
```

##### 初始化attr：

```c
#include <pthread.h>
/**
	使用默认属性值初始化 attr 指向的线程属性对象。
	调用该函数之后，可以通过各类相关函数（参见另见小节）设置对象的各项属性，随后该对象可在一次或多次 pthread_create (3) 调用中用于创建线程。
	对已经初始化过的线程属性对象再次调用 pthread_attr_init ()，会产生未定义行为。
	当不再需要线程属性对象时，应使用 pthread_attr_destroy () 函数销毁该对象。
	销毁线程属性对象不会对使用该对象创建出的线程产生任何影响。
	线程属性对象销毁之后，可以通过 pthread_attr_init () 对其重新初始化。
	对已销毁的线程属性对象进行其他任何操作，都会产生未定义结果。
	
	attr：设置属性值的结构体地址。
	return：
		成功：0
		失败： POSIX文档规定返回 ENOMEM。但是Linux确保该函数不会失败。如果需要考虑移植性，按照POSIX标准来
*/
int pthread_attr_init(pthread_attr_t *attr);
int pthread_attr_destroy(pthread_attr_t *attr);
```

```c
/**
	pthread_attr_setscope () 函数将 attr 指向的线程属性对象的竞争作用域属性设置为 scope 指定的值。竞争作用域属性定义该线程与哪些线程竞争 CPU 等资源。
POSIX.1 规定 scope 有两个可选值：
	PTHREAD_SCOPE_SYSTEM：
	该线程与系统内所有进程中、处于同一调度分配域（一个或多个处理器构成的组）内的其他所有线程竞争资源。PTHREAD_SCOPE_SYSTEM 类型的线程按照各自的调度策略和优先级相互调度。
	
	PTHREAD_SCOPE_PROCESS：
	该线程仅与同一进程内、同样以 PTHREAD_SCOPE_PROCESS 竞争作用域创建的其他线程竞争资源。PTHREAD_SCOPE_PROCESS 类型的线程按照各自调度策略与优先级，和本进程内其他同类线程进行调度。POSIX.1 未规定这类线程如何与系统中其他进程的线程，或是本进程内以 PTHREAD_SCOPE_SYSTEM 创建的线程进行资源竞争。
	POSIX.1 要求实现至少支持其中一种竞争作用域。
	Linux 支持 PTHREAD_SCOPE_SYSTEM，不支持 PTHREAD_SCOPE_PROCESS。
	在支持多种竞争作用域的系统上，若要让 pthread_attr_setscope () 设置的参数在调用 pthread_create (3) 时生效，调用者必须使用 pthread_attr_setinheritsched (3)，将属性对象 attr 的调度继承属性设置为 PTHREAD_EXPLICIT_SCHED。
	
	PTHREAD_SCOPE_SYSTEM:
		该线程会与系统内所有进程中、属于同一调度分配域（由一个或多个处理器组成的集合）的其他线程竞争资源。PTHREAD_SCOPE_SYSTEM 类型的线程将依据各自的调度策略与优先级相互调度。
	
	PTHREAD_SCOPE_PROCESS:
		该线程会与同一进程内，同样以 PTHREAD_SCOPE_PROCESS 竞争域创建的所有其他线程争夺资源。PTHREAD_SCOPE_PROCESS 类型的线程，会依据自身的调度策略与优先级，和进程内其他线程一同参与调度。POSIX.1 标准并未规定这类线程如何与系统中其他进程的线程，或是同一进程内以 PTHREAD_SCOPE_SYSTEM 竞争域创建的其他线程进行资源竞争。
		
	return:
		成功： 0
		失败：
		EINVAL：参数不合法
		ENOTSUP：POSIX文档标准有，但是Linux不会返回。
*/
int pthread_attr_setscope(pthread_attr_t *attr, int scope);
int pthread_attr_getscope(const pthread_attr_t *attr, int *scope);

/**
	pthread_attr_setguardsize () 函数将 attr 指向的线程属性对象的警戒大小属性设置为 guardsize 指定的值。
	如果 guardsize 大于 0，那么对于使用 attr 创建的每个新线程，系统会在线程栈的末尾分配一块至少为 guardsize 字节的额外区域，作为栈的警戒区域（但参见缺陷小节）。
	如果 guardsize 为 0，则使用 attr 创建的新线程不会配备警戒区域。
	默认警戒大小等于系统页面大小。
	如果已经在 attr 中设置了栈地址属性（通过 pthread_attr_setstack (3) 或 pthread_attr_setstackaddr (3)），即由调用者自行分配线程栈，那么警戒大小属性会被忽略（系统不会创建警戒区域）：此时应由应用程序负责处理栈溢出问题（可通过 mprotect (2) 在其分配的栈末尾手动设置警戒区域）。
	pthread_attr_getguardsize () 函数会将 attr 指向的线程属性对象的警戒大小属性存入 guardsize 所指向的缓冲区中返回。
*/
int pthread_attr_setguardsize(pthread_attr_t *attr, size_t guardsize);
int pthread_attr_getguardsize(const pthread_attr_t *attr, size_t *guardsize);

	同时设置栈地址与大小，等同于后面的 pthread_attr_setstackaddr + pthread_attr_setstacksize。
	pthread_attr_setstack () 函数将 attr 指向的线程属性对象的栈地址与栈大小属性分别设置为 stackaddr 和 stacksize 指定的值。这些属性规定了使用该线程属性对象 attr 创建的线程所使用栈的位置与大小。

	pthread_attr_getstack () 函数会将 attr 指向的线程属性对象的栈地址和栈大小属性，分别存入 stackaddr 和 stacksize 所指向的缓冲区中返回。
	
	return:
		0: 成功.

*/

int pthread_attr_getstack(const pthread_attr_t *attr,void **stackaddr, size_t *stacksize);

int pthread_attr_getstackaddr(const pthread_attr_t *attr, void **stackaddr);
```
