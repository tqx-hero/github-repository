## BM算法

##### BM算法同样也是为了解决BF（暴力算法）匹配失败时正文串指针回退问题，做到正文指针不仅不回退，反而会激进的往后加，甚至一次能跨很多步，在正文串很长的场景下效率非常高。

1. ###### 与KMP的正向匹配不同（KMP是从模式串的下标0开始，对齐正文串的0位置匹配），BM算法的匹配方向整好相反。BM是从后往前匹配，思路就是模式串与正文串对齐后从i-1往前进行匹配，如果有匹配失败的字符，那后面匹配好的字符或者当前正文串所在下标的字符咱们就可以在模式串中找看看有没有出现的，如果有就对齐，正文串指针直接往后跨一大步，继续在与模式串的末位往前一一比对。失败后继续重复以上操作，直到正文串结束匹配失败，或者匹配到模式串返回结果。

2. ###### 所以这个算法每次匹配失败会让正文串的指针往后挪动，有时挪动幅度甚至能等于模式串的长度，所以针对数据量比较大的正文串匹配时效率奇高。下面就讲讲这个算法的具体实现。

   1. ##### 既然是从后往前匹配，首先想到的就是与KMP相同的，如果匹配到i位置时匹配失败了，那从i~len-1（len为模式串长度）区间内的子序列是肯定都匹配的。那既然这些后缀都匹配，咱们只需要找到这个模式串在这个后缀之前最晚出现的位置，如果有这个位置（就是这个后缀在模式串中可以多次找到），那咱们把这几个后缀字符所在的位置与正文串的那几个i~len-1的对齐上，这几个字符就匹配了。在这基础上继续从后面往前去比较就可以了。

   2. ##### 所以找这个后缀位置就成了解决这个问题的关键，BM算法称这个后缀叫好后缀。好后缀是指以当前下标i为界，i+1~len-1区间内的字符子序列中能在0~i-1区间内找到的相同最长字符子序列的起始下标。

   3. ###### 举个例子：模式串=[CACTCAC]，对应好后缀的下标分别为：prefixIndex[]:[-1,0,0,0,1,4,-1],好后缀长度分别为：[0,1,1,3,2,1,0],

   4. ###### 第一位与最末尾没有前缀或者后缀，所以长度为0，下标设为-1。

   5. ###### 下标1，值为A，前缀C，后缀CTCAC，从后往前匹配，最长匹配好后缀是C，长度1，坐标是0.

   6. ###### 下标2，值为C，前缀CA，后缀TCAC。从后往前匹配，好后缀C，长度1，坐标0.

   7. ###### 下标3，值T，前缀：CAC，后缀CAC。前后缀相同长度3，坐标0.

   8. ###### 下标4，值C，前缀：CACT，后缀AC，好后缀为AC，长度2，起始下标1.

   9. ###### 下标5，值A，前缀CACTC，后缀C，好后缀C，长度1，下标4.

   10. ###### 下标6为末尾，没有好后缀，长度0，下标-1.

3. ##### 找到好后缀以后，接下来就是根据prefixIndex数组的下标，当对应下标j与正文串匹配失败时，查找prefixIndex[j]的值找到好后缀的初始下标，与正文串对应模式串j，即匹配失败位置之后的区间[j+1,len-1]，将相对应的好后缀接到对应位置，让这个后缀与正文串相同字符对齐，正文串指针后移，后移步数jmp=j-prefixIndex[j],这时正文串指针为i+jmp，继续从后往前匹配。循环直到找到子串或者正文串搜寻结束。

4. ##### 除了好后缀，BM算法还有一个坏字符的规则。这个规则就是能够让字符串在匹配时可以直接一下甚至能跨一整个模式串的形式。具体思路如下：

   1. ###### 当匹配到i位置失败时，我先看一下这个位置的正文串字符是什么，比如是a，既然不匹配，我就看看a在我这个模式串中最后出现的位置在哪。如果我模式串中有a字符，那我就让它与正文串的a对齐，然后在让正文串指针后移，继续与模式串从后往前匹配(这里得需要看下a的位置是在i位置前还是后，前的话可以直接对齐，如果是在i后面，只能让正文串与模式串都往后挪一位。因为i往后的区间内字符是已经匹配过得，如果对齐的话，模式串往后倒着走了)；如果a字符在模式串中直接没有，那这个字符相关的直接不用比了，直接跨一个模式串的区间，跨过这个坏字符a，从后面+模式串长度开始重新匹配。

   2. ###### 所以还是要预处理模式串，找出每个下标对应字符所出现在模式串的最后下标，记录下来，可以用一个int数组来存放（map也可以），数组存放的话，新建一个256长度的int数组，以字符的ASCII值为下标，存放模式串中的字符所在下标i，如下：

      ```java
        int[] badChars = new int[256];
      for (int i = 0; i < n; i++) {
          //坏字符的处理
          //以字符的ASCII值为下标将字符在模式串中最后出现的位置放到badChars数组中
          badChars[sArr[i]] = i;
      }
      ```

   3. ###### 与好后缀处理模式相同，在下标j不匹配时，查询对应下标字符所在的最晚出现位置，计算跳跃步数：jump=j-badChars[strArr[p]]，然后再计算i的下标即可。

5. ##### 好后缀与坏字符这俩规则可以同时计算，根据计算出的跳跃步数jump，哪个大，哪个能让正文串下标i跳的更远，就选哪个，最后i+=jump。这样在大量字符串文本中查找出模式串的搜索效率会变态的快。整体代码如下：

   ```java
   public class BMAlgorithm {
   
       public static int getIndex(String str, String s) {
           if (str == null || s == null || str.isEmpty() || s.isEmpty() || s.length() &gt; str.length())
               return -1;
           char[] sArr = s.toCharArray();
           char[] strArr = str.toCharArray();
           var n = sArr.length;
           int m = strArr.length;
   
           //记录每个字符在模式串中出现的最末index
           //坏字符的最后下标存储结果
           int[] badChars = new int[256];
           Arrays.fill(badChars, -1);
   
           //好后缀处理解
           //好后缀即表示以当前下标为界后面的子串在前面子串出现的最长子串，用于在匹配过程中
           //发生匹配失败时让匹配成功部分直接前挪到正文串相关位置，不需要再次回溯
           //1、好后缀的最大长度
           int[] suffix = new int[n];
           //2、好后缀的起始下标
           int[] prefixIndex = new int[n];
           Arrays.fill(prefixIndex, -1);
           for (int i = 0; i &lt; n; i++) {
               //坏字符的处理
               //以字符的ASCII值为下标将字符在模式串中最后出现的位置放到badChars数组中
               badChars[sArr[i]] = i;
   
               //好后缀的处理
               //以当前下标为界划分两个子串序列
               //跳过首尾无意义的两个下标
               if (i == 0 || i == n - 1)
                   continue;
               //定义好后缀检测的指针
               int h = i - 1, t = n - 1;
               //记录好后缀的长度与起始下标
               int size = 0, cur = -1;
               //不相同则继续从后往前找
               //查看记录的长度是否超过suffix中记录的长度
               //超过则覆盖记录,并清空长度与下标的临时变量
               //清空临时记录，重新开始计数
               //相同则开始记录下标与长度，指针前移继续匹配
               //循环结束，再次查看记录，超过长度的再次记录
               for (; h &gt;= 0 &amp;&amp; t &gt; i; h--) {
                   if (sArr[h] != sArr[t]) {
                       if (size &gt; 0)
                           break;
                       continue;
                   }
                   cur = h;
                   t--;
                   size++;
               }
               if (size &gt; suffix[i]) {
                   suffix[i] = size;
                   prefixIndex[i] = cur;
               }
           }
           for (int i = n - 1; i &lt; m; ) {
               if (sArr[n - 1] != strArr[i]) {
                   i++;
                   continue;
               }
               //正文串起始指针
               int p = i;
               //子串起始指针，末尾开始往前匹配
               int j = n - 1;
               for (; j &gt;= 0 &amp;&amp; strArr[p] == sArr[j]; p--, j--) ;
               //如果都匹配相同,直接返回下标位置
               if (j &lt; 0)
                   return ++p;
               //如果匹配失败，记录当前正文串中下标的字符
               //找到该字符在模式串中最后出现的的下标
               //如果找到，将模式串中该字符与正文串中的这个对齐
               //再重新在模式串中倒着比较
               int b = badChars[strArr[p]];
               int jump = b &lt; 0 ? n : j - b;
               //如果出现跳跃步数为0或者负数的情况
               //比如b的位置，即最后出现的下标超过当前指示的下标
               //此时jump为负数，这样会往回退
               //为了避免这种情况，需要强制让它跳一步
               if (jump &lt; 1)
                   jump = 1;
   
               //好后缀的情况，要移动的步数
               if (prefixIndex[j] != -1) {
                   //计算好后缀情况下要移动的步数
                   int jmp = j - prefixIndex[j];
                   //取两者最大值
                   jump = Math.max(jmp, jump);
               }
               i += jump;
           }
           return -1;
       }
   
       public static void main(String[] args) {
           String str = &quot;TTTTCACTCAC&quot;;
           String s = &quot;CACTCAC&quot;;
           System.out.println(getIndex(str, s));
       }
   
   }
   ```

##### 相比较KMP的稳健，BM的处理更大胆激进，好后缀与坏字符的两种规则让BM算法能让字符匹配失败时直接跳过没必要检测的字符，指针跳跃更快，针对大文本字符串有奇效。
