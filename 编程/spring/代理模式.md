## 代理模式：

### 1.静态代理

##### 一个代理只能代理一个对象，硬编码方式实现。

如下方Boss与接待员的关系：

```java
public class Boss {
    public void metting(String name) {
        System.out.println("boss接见了 " + name);
    }
}

public class StaticProxy extends Boss {
    @Override
    public void metting(String name) {
        if (name.equals("张三")) {
            super.metting(name);
        }
    }
    
        public static void main(String[] args) {
        Boss proxy = new StaticProxy();
        proxy.metting("张三");
    }
}

```

### 2.动态代理

##### 	自动为被代理对象生成代理对象，不需要硬编码，而且能对被代理对象进行方法增强。	

##### 	动态代理分为：JDK动态代理和CGLIB动态代理。

####   A.JDK动态代理

##### 	JDK原生支持的代理方式。被代理的对象必须实现至少一个接口。

> [!IMPORTANT]
>
> #### 注意：由于JDK动态代理的代理类是重写的接口里方法而非目标类中的，所以如果目标类中有非接口重写的方法，代理类不会生成这个方法的，这种情况就不能使用JDK动态代理，只能使用CGLIB实现。
>
> #### spring的AOP默认都是使用CGLIB实现，可放心使用



```java
public class JDKProxy {
    public static void main(String[] args) {
         //设置该属性就可以将jdk动态代理生成的代理类导出到{当前目录}/jdk/proxy1下面
        System.getProperties().put("jdk.proxy.ProxyGenerator.saveGeneratedFiles", "true");
        
        //生成JDK代理对象
        //这里的强转对象必须是接口，因为返回的实例是代理对象，不是被代理对象，只能强转成接口，不能强转为实现类
        IJDKDemo o = (IJDKDemo) Proxy.newProxyInstance(JDKDemo.class.getClassLoader(),
                JDKDemo.class.getInterfaces(),
                new JDKInvokerHandler(new JDKDemo()));

        o.metting("张三");
    }
}
```

```java
public class JDKInvokerHandler implements InvocationHandler {
    private Object target;

    public JDKInvokerHandler(Object target) {
        this.target = target;
    }
    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        System.out.println("调用方法前");
        Object o = method.invoke(target, args);
        System.out.println("调用方法后");
        return o;
    }
}
```

####   C.两者比较:

##### 	JDK动态代理是实现传入的接口形式生成的，底层机制是通过类加载器加载目标字节码文件生成一个代理类，这就是代理对象，调用方法时先调用InvokerHandler实现类的invoke方法，根据业务对方法增强后用户自己显式通过反射的方式调用被代理对象的相关方法。

##### 	由于反射方式invoke需要进行权限验证、基本数据类型包装，无法进行JIT优化，所以传统反射实现较慢。但在1.8之后版本，jdk动态代理在调用方法时引入MethodHandle代替传统的method.invoke方式，减少了反射的安全检查与参数校验等步骤，而且支持JIT优化，效率大大提升，当前jdk动态代理仅比CGLIB稍慢一点点。

###### 在生成的代理类中就会发现，代理类除了生成了所需要的几个方法外，新生成了一个MethodHandles返回值的方法，这个方法就是生成方法句柄的。
