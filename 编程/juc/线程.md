#### start()和run()的区别：

​	类型：

​		run是同步调用方法，不会创建新线程，start是开启新线程，异步执行。

​	作用：

​		run仅仅是存放代码，start是调度启动线程。

​	线程数量：

​		run不会创建线程，执行顺序与主线程内方法一致，start是创建新线程。

​	调用方法：

​		run方法是个普通方法，可以调用无限次，start是开启线程的，只能调用一次，因为线程不能重复创建。

### sleep（）

​	静态方法，调用时必须添加睡眠时间；

​	随时可以调用，在哪调用就在它所在的线程进入睡眠状态，达到线程阻塞的目的。

​	注意：sleep()方法不释放锁，获取锁的线程如果在没释放锁的情况下sleep，锁一直不会释放。

​	在睡眠时如果调用打断方法会抛出异常。

​	可以用时间工具类来进行睡眠

```java
public class Sleep {

    public static void main(String[] args){
        try {
            TimeUnit.SECONDS.sleep(1);
        } catch (InterruptedException e) {
            throw new RuntimeException(e);
        }

    }
}
```



### yield()

​	线程让步，静态方法，可通过Thread.yield();调用，使当前线程放弃拥有的CPU使用权，但具体其他线程能不能抢到CPU的使用权得看CPU的具体调度情况。

```java
public static void main(String[] args) {

    Thread thread1 = new Thread(() -> {
        System.out.println("线程1启动");
        Thread.yield();
        for (int i = 0; i < 100; i++) {
            System.out.println(Thread.currentThread().getName() + ":" + i);
        }
    }, "线程1");
    Thread thread2 = new Thread(() -> {
        for (int i = 0; i < 100; i++) {
            System.out.println(Thread.currentThread().getName() + ":" + i);
        }
    }, "线程2");

    thread1.start();
    thread2.start();
}
```

### interrupt()

​	给线程打上中断标记，实际上不会立马中断线程。源码如下：

```java
public void interrupt() {
    if (this != Thread.currentThread()) {
        checkAccess();

        // thread may be blocked in an I/O operation
        synchronized (blockerLock) {
            Interruptible b = blocker;
            if (b != null) {
                interrupted = true;
                interrupt0();  // inform VM of interrupt
                b.interrupt(this);
                return;
            }
        }
    }
    //这里只是给线程打个中断标记，不会中断线程执行
    interrupted = true;
    // inform VM of interrupt
    interrupt0();
}
```

### isInterrupted()和interrupted()方法：

​	两者都是可判断线程是否被中断，区别：

​	isInterrupted()是实例方法，需要实例对象去调用

```java
Thread.currentThread().isInterrupted()
```

只判断线程是否有interrupted()打上的中断标记，有则返回true，无则返回false，不会清除标记。

源码如下：

```java
//仅仅查看中断标记是否存在
public boolean isInterrupted() {
    return interrupted;
}
```

但是isInterrupted()不同，该方法是静态方法：

```java
Thread.interrupted()
```

##### 在判断是否有中断标记之外，如果有还会把中断标记清除。

```java
public static void main(String[] args) {
    Thread thread = new Thread(() -> {
        for (int i = 0; i < 10; i++) {
            System.out.println(Thread.currentThread().getName() + ": " + i);
        }
        //返回true
        System.out.println("线程是否被打断：" + Thread.currentThread().isInterrupted());
        //返回true，同时清除中断标记
        if (Thread.interrupted()) {
            //返回false，标记已被静态方法清除
            System.out.println("线程是否被打断：" + Thread.currentThread().isInterrupted());
        }
    });
    thread.start();
    thread.interrupt();
    System.out.println("主线程");
}
```

源码如下：

```java
public static boolean interrupted() {
    Thread t = currentThread();
    boolean interrupted = t.interrupted;
    // We may have been interrupted the moment after we read the field,
    // so only clear the field if we saw that it was set and will return
    // true; otherwise we could lose an interrupt.
    //判断是否有中断标记
    if (interrupted) {
        //如果有标记，将标记清除
        t.interrupted = false;
        //调用native方法清除中断标记
        clearInterruptEvent();
    }
    return interrupted;
}
```

##### 同样sleep()也会清除中断标记。当线程正在睡眠中，执行打断指令时会抛出打断异常，同时清除中断标记，继续执行后续代码。

```java
public static void main(String[] args) {
    Thread thread = new Thread(() -> {
        for (int i = 0; i < 10; i++) {
            System.out.println(Thread.currentThread().getName() + ": " + i);
        }
        while (true) {
            try {
                //睡眠途中执行中断指令，抛出异常，清除中断标记，如果不重新设置中断标记，后续指令都会执行
                TimeUnit.SECONDS.sleep(10);
            } catch (InterruptedException e) {
                e.printStackTrace();
                //可以在这里再次设置
                //Thread.currentThread().interrupt();
            }
			//如果上方异常处理中没有再次设置中断，后续的判断都为false
            System.out.println("线程是否被打断：" + Thread.currentThread().isInterrupted());
            if (Thread.interrupted()) {
                System.out.println("线程是否被打断：" + Thread.currentThread().isInterrupted());
            }
        }
    });
    thread.start();
    thread.interrupt();
    System.out.println("主线程");
}
```



### join()

​	让当前方法的线程进入等待队列。注意这里是当前方法的线程，不是调用join方法的对象。

```java
public static void main(String[] args) throws InterruptedException {
    Thread thread = new Thread(() -> {
		//这里才是子线程执行的方法！！！！！一定不要混淆
        try {
            TimeUnit.SECONDS.sleep(5);
        } catch (InterruptedException e) {
            throw new RuntimeException(e);
        }

        System.out.println("子线程执行完毕");
    });

    thread.start();
    //调用join方法的是子线程对象，但是执行该方法的线程是主线程，这里是把执行方法的线程放到等待队列，而不是子线程
    thread.join();
    System.out.println("主线程执行完毕");
}
```

源码如下：

```java
public final synchronized void join(final long millis)
throws InterruptedException {
    if (millis > 0) {
        if (isAlive()) {
            final long startTime = System.nanoTime();
            long delay = millis;
            do {
                wait(delay);
            } while (isAlive() && (delay = millis -
                    TimeUnit.NANOSECONDS.toMillis(System.nanoTime() - startTime)) > 0);
        }
    } else if (millis == 0) {
        while (isAlive()) {
            //这里是调用native方法将执行该方法的线程从阻塞队列取出并放入等待队列
            //注意这里指的是执行方法的线程，不是执行方法的对象，千万不要搞混
            wait(0);
        }
    } else {
        throw new IllegalArgumentException("timeout value is negative");
    }
}
```



### 守护线程

​	创建线程时可以通过setDaemon(true)来设置该线程是守护线程。

​	守护线程的特点是当所在方法的线程结束后，守护线程会立刻停止执行并立刻结束。

```java
public static void main(String[] args) {
    Thread t1 = new Thread(() -> {
        for (int i = 0; i < 100; i++) {
            System.out.println(i);
        }
    });

    t1.setDaemon(true);
    t1.start();
    System.out.println("主线程结束");
}
```

上方子线程是守护线程，主线程结束后会立即结束，不会等执行完循环才结束。

###### 注意：守护线程setDaemon(true)必须放在线程启动之前，如果在线程启动之后执行会抛出异常。

源码如下：

```java
public final void setDaemon(boolean on) {
    checkAccess();
    //这里在设置守护线程之前先查看线程对象（this）是否存活，存活就会抛异常，所以守护线程必须在线程启动之前进行设置
    if (isAlive()) {
        throw new IllegalThreadStateException();
    }
    daemon = on;
}
```

##### 守护线程应用场景：

​	垃圾回收线程；tomcat处理web请求的线程

### 线程的六种状态：

​	1、NEW：新建状态，创建了对象，还没有start()

​	2、RUNNABLE:运行中，已经调用了start

​	3、BLOCKING:阻塞，对共享变量加锁，线程正在等待另一个线程解锁的状态

​	4、WAITING:等待，调用了wait()、join()等没有设置时间的方法。

​	5、TIME_WAITING:有时长的等待，调用了wait(time)、sleep(time)、join(time)的方法，超过等待时长停止等待

​	6、TERMINATED:终止，线程关闭



线程的生命周期是不可逆的，一旦进入runnable状态就不能进入new状态，同样，进入终止状态就不能转换到其他状态。

除了new和终止，其他四种状态可以互相转化。

​	new和终止状态只能进行一次。

​	wait()或wait(time)可以通过notify()或notifyAll()、LockSupport.unpark()来唤醒，如果没有高并发的CPU资源竞争或者幸运的获得了相关的锁，进入runnable状态，存在高并发且没有获得锁，则进入阻塞状态。

​	runnable和blocking状态可通过sleep、join()、wait()、LockSupport.park()让线程进入两种等待状态。

​	runnable在高并发竞争共享资源时，未获得锁的线程进入blocking状态。

​	blocking通过获取锁可以进入runnable状态。
