### 循环依赖

有两个类A、B，在注入阶段A依赖B，而B有依赖A，形成循环依赖的现象。

依赖形式分为构造器注入阶段依赖和setter注入阶段依赖，两者不相同。

###### 1、构造器注入阶段如下：

```java
@Component
public class A {
    private final B b;

    public A(B b) {
        this.b = b;
        System.out.println("A实例化成功...,注入的B对象是：" + b.getClass().getName());
    }
}
```

```java
@Component
public class B {
	//构造器注入
    private final A a;

    public B(A a) {
        this.a = a;
        System.out.println("B实例化成功,a的实例化对象是：" + a.getClass().getName());
    }
}
```

当前的状况spring无法解决，因为构造器属于bean生命周期的实例化阶段去调用的方法，实例化阶段传入未实例化的对象，两者互相需要对方的实例才能生成自身的实例，达成了死锁，谁也生成不了实例，所以两个对象都创建不出来。

这种情况可以通过让一方先生成一个代理对象的方式去解决，如下：

```java
@Component
public class B {

    private final A a;

    public B(@Lazy A a) {
        this.a = a;
        System.out.println("B实例化成功,a的实例化对象是：" + a.getClass().getName());
    }
}
```

spring提供的懒加载机制，只要一方声明懒加载，在B的实例化阶段，由于A是懒加载，就是说在B需要构造器实例化时，spring会先创建A实例的代理对象（CGLIB/JDK动态代理，取决于该类是否是接口的实现类），B拿到A的代理对象进行实例化，实例化完成后，A在拿到B的真实对象后进行实例化，生成真实对象。本质还是通过懒加载机制提供代理对象的方式解决的，代理模式的机制应用。

运行结果如下：

```java
A实例化成功...,注入的B对象是：com.spring.sircel.B$$EnhancerBySpringCGLIB$$60f26133
B实例化成功,a的实例化对象是：com.spring.sircel.A
```



###### 2、setter注入形式：

多个类是在通过setter方法注入形成的循环依赖：

```java
@Component
public class A {
    @Autowired
    private  B b;

    void sayA() {
        System.out.println("A的对象是=" + A.class.getName());
    }
}
```

```java
@Component
public class B {
    @Autowired
    private A a;

    public void sayB() {
        System.out.println("B的实例对象=" + B.class.getName());
    }
}
```

此时没有通过构造器注入，那么spring就可以通过调用A、B各自的无参构造方法进行实例化。即new A()和new B()。

根据bean的生命周期，两者在实例化成功后就进行DI（即依赖注入）。spring是设置了三级缓存来解决的setter循环依赖。
